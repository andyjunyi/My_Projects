# AI 協作開發慣例（Andy 老師專用）

## 指令驅動開發

Andy 習慣在專案中建立 `instructions.txt` 或 `CLAUDE.md` 來定義 AI 的格式要求。

### instructions.txt 範例（cap-eng 風格）
```markdown
# 給 AI 的專案指令

## 單字資料格式
- KK 音標用斜線包圍：/ˈpipəl/
- 中文註釋簡潔，多義詞用分號隔開
- 使用民國年份：102–114

## 網頁風格
- 淺色主題
- 藍色系漸層 header
- 白色圓角卡片
```

### CLAUDE.md 範例（2000-voc 風格）
```markdown
# Vocabulary Project — AI Rules

## Output Format
- 詞性標示：(名)(動)(形)(副)(介)
- 難度標記：🟢基礎(A1-A2) 🟡中級(B1) 🔴進階(B1+)
- 例句 10-20 字，貼近學生生活
- 說明用繁體中文
```

## 常見 AI 協作模式

### 模式 1：資料生成
```
你 → 描述需求（格式、數量、內容要求）
AI → 產生結構化資料（JSON / CSV / Excel）
你 → 手動校對後匯入專案
```
**適合**：單字庫、例句、測驗題

### 模式 2：網頁生成
```
你 → 給 layout 描述 + 資料格式
AI → 生成完整的 HTML/CSS/JS
你 → 下載後開啟測試
```
**適合**：原型開發、小型工具頁

### 模式 3：資料分析
```
你 → 上傳 PDF 或貼文字
AI → 提取單字、統計詞頻、標註 KK 音標
你 → 校對輸出結果
```
**適合**：會考/學測試題分析

### 模式 4：功能迭代
```
你 → 現有程式碼 + 修改需求
AI → 生成 patch 或完整檔案更新
```
**適合**：既有專案維護升級

## 格式要求清單（複製用）

在給 AI 的提示中，建議包含以下區塊：

### 📋 必填要求
- [ ] 繁體中文（zh-TW）
- [ ] KK 音標（國中層級）/ 英文縮寫詞性（高中層級）
- [ ] 詞類標示格式（如 `(名)` 或 `n.`）
- [ ] 例句附中文翻譯
- [ ] 民國年份 / 學年度
- [ ] 分級標示（核心300 / 鞏固450 / 1200單 / 800單）

### 🎨 設計要求
- [ ] 淺色主題
- [ ] 藍色系漸層 header
- [ ] 白色圓角卡片（12–14px）
- [ ] Nunito + Noto Sans TC 字型
- [ ] 響應式設計（支援手機）
- [ ] 彩色 Badge 區分詞性
- [ ] hover 上移效果
- [ ] sticky 過濾器／導航

### 🔧 技術限制
- [ ] 純前端可行（除即時通訊外）
- [ ] 資料嵌入 HTML/JS（不需後端）
- [ ] Excel 為主要資料庫格式
- [ ] Google Apps Script 作為唯一後端

## 專案初始化模板

### 純靜態頁模板
```
請幫我製作一個英文單字查詢網頁。
格式要求：
[貼上上面 📋 + 🎨 的 checklist]
資料如下：
[貼上資料]
```

### React 專案模板（gsat-english-hub 風格）
```
請幫我建立一個 React + Vite + Tailwind CSS 的學習平台。
需求：
1. [功能描述]
2. 使用 React Router 做 SPA 路由
3. 資料以 JS module 靜態載入
4. Tailwind CSS 為主，輔以 CSS Modules
5. 部署目標：Vercel
```

## 注意事項
1. AI 生成的 KK 音標需要人工校對（常有錯誤）
2. PDF 試題提取後建議手動抽查
3. 例句是否需要調整長度（8–20 字為佳）
4. 同一專案中資料格式要保持一致
5. 記得建立 `instructions.txt` 給下一次 AI 會話使用
